# Level 3: Agent (单兵自治) 专题研究中心

> **专题定位**：本目录专门用于攻坚 **Level 3: Autonomous Agent（单兵闭环自治）** 在工业软件工程中的落地瓶颈。核心聚焦于两大核心课题：
> 1. **反工具绑定批判**：深度解构为什么我们不能将工程基础设施绑定在 `omp` (Oh My Pi)、`Aider`、`Claude Code` 等具体 CLI 工具上；
> 2. **工具无关架构设计（Tool-Agnostic Architecture）**：如何通过“标准化契约 + 抽象驱动层 + 物理沙盒隔离 + 外部质量门禁”，实现底座执行引擎的即插即用（Pluggable Execution Engine）。

### 核心论点摘要

1. **工具是易逝的消费品，契约才是长期的生产力资产**：
   - 市场上每隔 3~6 个月就会冒出新的“明星 Agent 工具”（从 AutoGPT、GPT-Engineer，到 Aider、OpenHands，再到 Claude Code、omp）。
   - 如果研发流程与特定工具的参数、交互习惯或配置格式深度耦合，团队将陷入永无止境的工具重构泥潭。
2. **“重客户端”天然与“自动化工作流”冲突**：
   - 像 `omp`（Oh My Pi）这类产品，本质上是定位给**人类在终端交互操作的“全功能装甲车”**（内置 LSP、内嵌 DAP 调试器、内嵌多子 Agent）。
   - 当我们需要将其接入 Level 5 的自动化状态机、CI/CD 门禁或无头（Headless）批量构建时，重客户端的 TUI 界面、缺乏结构化状态输出、配置侵入性反而成为最大的系统阻碍。
3. **“工具无关”的解法是把核心控制权外置（Inversion of Control）**：
   - 把测试防护移到文件系统与 CI 门禁（只读权限 + Diff 隔离）；
   - 把熔断逻辑移到主控状态机（计数器与快照）；
   - 把算力控制移到统一网关（LiteLLM 虚拟 Key）；
   - **底层单兵 Agent 沦为纯粹的“代码补丁生成器（Patch Generator）”，想换就换。**
