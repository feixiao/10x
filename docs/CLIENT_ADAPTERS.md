# 多客户端适配指南

## 目标

OMP、OpenCode 与 Claude Code 共用项目级研发契约和角色定义；客户端配置负责把角色交给各自的 Agent、Skill 或独立会话，并配置模型连接和工具权限。共享契约不依赖某个客户端的 Agent API。

## 共用资产

- `AGENTS.md`：项目技术栈、命令、边界、验证要求。每个项目根据真实仓库填充，不把技术栈示例当成硬编码要求。
- `roles/core/`：规划协调者、实现者、独立审查者、只读调查者的可移植角色契约。
- `roles/`：可选的特定工作流角色。语言模板已有的 `master-dispatcher`、`worker-developer`、`independent-auditor` 等角色服务于 `project-autopilot`，是可选自动驾驶流程，不是所有任务都需要的基础岗位。
- `tasks/`：任务契约和状态记录；小任务可以直接使用契约而不搭建调度器。

运行 `scripts/install-harness.sh <cpp|go|python|android> <项目路径>` 会安装技术栈模板和共用角色到 `roles/core/`。也可以直接复制 `templates/common/roles/` 到目标仓库的 `roles/core/`。

## 客户端映射

| 共用职责 | OMP | OpenCode | Claude Code |
|---|---|---|---|
| 规划协调 | `plan` 角色或当前会话 | planner Agent 或当前会话 | Plan 模式或规划 Agent |
| 实现 | `default` 角色或当前会话 | build/implement Agent | 主会话或实现 Agent |
| 独立审查 | 独立只读子 Agent/会话 | reviewer Agent/会话 | reviewer Agent/独立只读会话 |
| 只读调查 | `smol`/只读子 Agent | explore Agent | Explore Agent 或只读子 Agent |

表中是职责映射，不保证每个客户端版本都具备相同的 Agent 类型或权限隔离能力。若没有对应机制，把 `roles/core/<role>.md` 内容作为当前会话任务说明，并用客户端权限与独立工作区实现必要隔离。

## Magpie 模型接入

在每个客户端自身配置中设置 Magpie 提供的模型端点、认证和模型 ID。复用角色职责，不要求不同客户端采用相同配置格式。模型路由建议按任务能力选型：低成本模型承担快速只读检索；通过真实验收验证后再把可界定的小任务交给本地模型；复杂规划、疑难排查和关键审查使用经过验证的强模型。不要把端点、密钥或未验证的模型名写进共享角色文件。

启用前核实各客户端支持的 API 协议、工具调用、上下文长度和模型 ID，并用无敏感数据的小任务确认端到端可用。不要把代理商的“模型名称可选”误当成已具备全部工具能力。

## 默认任务闭环

1. 人确认目标、非目标和风险；规划角色写出契约和验收标准。
2. 实现者在明确范围内编码并运行验收命令。
3. 独立审查者只读检查 diff、测试变更和验证证据。
4. 人确认集成、合并和发布；发布由项目现有 CI/CD 执行。
5. 仅在任务足够独立、文件所有权清晰时用 Worktree 并行。每个工作区只安排一个写入者。

MCP、自动修复循环、集中式 LiteLLM、远端运维权限都不是接入前置条件。只有重复工作形成明确需求后再增加相应能力；角色提示词本身不构成安全隔离。
