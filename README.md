# 10x：研究现成 AI 工具如何加速研发

本项目整理公开研究、工具现有能力和可复用的研发工作方式。目标是缩短**通过验收的交付时间**，同时观察审查、返工、缺陷和工具成本。“10x”是项目名，不是已证明的提效倍数。本仓库是研究文档，不是编码 Agent 或自动化平台。

## 从哪里开始

- [跨工具实践指南](./AGENT_ENGINEERING_GUIDE.md)：Agent 交付闭环、并行边界、权限和效果衡量；附 C++、Go、Python 实操项目。
- [统一规则与跨工具规范](./UNIFIED_AGENT_RULES.md)：Claude Code、omp 与 Pi 的统一规则架构、契约定义与多语言工程约束。
- [C++、Go、Python 动手实验](./agent-lab/README.md)：本机可构建的三个同规格费用汇总 CLI，用 Agent 完成类别筛选，并运行各语言测试与验收命令。
- [现成工具与证据](./AI_WORKFLOWS.md)：已有研究说明了什么；何时用单 Agent、独立审查或多 Agent，以及 Claude Code 可直接使用的能力。
- [Pi 使用版](./PI_WORKFLOWS.md)：Pi 单会话、只读审查、独立 worktree 会话和集成验收。本机核对版本为 Pi 1.1.0。
- [动手练习](./STEP_BY_STEP.md)：从全新 Go 项目开始，先审阅三文件计划，再由两个 Agent 分工开发、单测、集成与独立验收；该练习不测提效。

## 当前工作假设（待真实任务验证）

1. 有现成测试、边界清楚的小改：先用一个编码 Agent 完成实现和局部单测，再由项目 CI 和真实行为验收。Pi 或 Claude Code 都可承担。
2. 搜索、日志调查或独立审查占用大量上下文：用只读子 Agent 或独立会话返回证据；让主会话集成决策。
3. 大量独立迁移可考虑 Claude Code `/batch`；需要成员沟通的复杂任务可考虑实验性的 Agent Teams；Pi 基础版不内置子 Agent，多会话并行需独立管理和集成。
4. 并行任务按文件或模块划清归属。各自单测通过后，仍须在**集成版本**运行回归与验收。无法自动判断的协议、并发、媒体与性能结论要有可重复的实测证据。

已有研究既观察到提效，也观察到减速；其任务、人员与工具版本不同，不能直接推算本人的收益。研究数字、来源和限制详见 [工具选型指南](./AI_WORKFLOWS.md)。遇到具体选型争议时，再用少量真实任务记录目标仓库版本、工具与模型、验收结果、准备与等待时间、审查与返工、费用；根据这些数据修订建议。无需先建设新编排器或开展固定周期的实验。
